Working principles

  1. Keep the raw file untouched. The original CBS Public Use File is never overwritten - every step reads it and writes a new derived dataframe. This keeps a clean baseline we can always fall back to.
  2. Convert CBS non-response codes to real missing values. The Social Survey reserves two special numeric codes inside otherwise normal columns:
    • 888888 - the respondent chose "don't know" or refused to answer.
    • 999999 - the question was not applicable to that respondent (skipped because of an earlier filter, e.g. salary questions for someone who is not employed).
    Both are replaced with NaN so that any numeric operation (mean, median, correlation, model imputation) treats them as missing instead of averaging a literal 888888 into the data.
  3. Document missingness, don't silently drop rows. Dropping every respondent with any missing value would delete most of the sample and bias it toward one demographic. Instead the missing pattern is measured per column and stored, and imputation happens inside the modeling pipeline (median-imputation per CV fold).
  4. Do not scale features here. StandardScaler and any other learned transformation live inside the sklearn Pipeline so they are re-fit on each training fold - this prevents test-fold information from leaking into training.
  5. Preserve provenance. Every derived variable (e.g. financial_risk_score) traces back to the raw CBS codebook, and the codebook itself is carried alongside the cleaned data so any label or category can be re-verified.

Financial themes in the survey

Generated with the open-source wordcloud Python library (WordCloud.generate_from_frequencies). We hand-picked a set of finance-related items in the raw Social Survey 2024 file (pension, study fund, bank, credit, savings, digital currency, income, financial planning, and related themes) and passed the library a {term: weight} dictionary. The weight for each term is either the number of respondents who answered "yes" to the underlying question, or - for non-binary items - the number of respondents with a valid non-missing answer. The library then chooses a font size proportional to that weight (with relative_scaling=0.55, so a term twice as popular is noticeably larger but the biggest word does not dominate the whole canvas), and lays the words out with a greedy no-overlap packing algorithm on a 1200x520 canvas: it walks candidate positions and puts a word in the first spot where its bounding box does not collide with any already-placed word. Colors are decorative only (viridis colormap, assigned at random per word) - they carry no information. Two words being next to each other in the cloud does NOT mean they are semantically related; adjacency is purely a byproduct of the packing order. Only the font size is meaningful, and it maps directly to how many of the 6,907 respondents that theme applies to.

Performance figures

Diagnostic plots for the winning configuration - four hyperparameter sensitivity curves and one test-set summary panel (confusion matrix, ROC, precision-recall).

Fig_1 - n_estimators sensitivity - Accuracy, Recall and F1 as the number of boosting trees changes. The red dashed line marks the value GridSearchCV chose for the final model.

Fig_2 - learning_rate sensitivity - Same three metrics as above but sweeping the boosting learning rate. Shows how sensitive the model is to that single hyperparameter, with the others held at their best values.

Fig_3 - max_depth sensitivity - Effect of individual tree depth on Accuracy, Recall and F1. Deeper trees fit more complex patterns but can overfit; the red line is the depth that GridSearchCV picked.

Fig_4 - Decision threshold sensitivity - How the classifier's Recall and F1 shift as we move the probability cutoff for the positive class. Lower thresholds catch more at-risk respondents (higher Recall) at the cost of Accuracy.

Fig_5 - Test-set summary - three panels for the selected final model: confusion matrix (predicted class vs actual class), ROC curve (true-positive rate vs false-positive rate at every threshold, with area-under-curve), and Precision-Recall curve (behavior on the positive class alone).

SHAP interpretation

How individual features drive predictions of the selected model, and where its wrong decisions concentrate.

Fig_6 - SHAP beeswarm, top 5 features - each dot is one respondent. Horizontal position = that feature's SHAP contribution to the model's prediction; color = the feature's value (blue low, red high). Reveals whether a feature pushes the prediction up or down, and whether the effect depends on its value.

Fig_7 - SHAP mean-absolute importance, top 5 features - a global ranking of the same features by average magnitude of contribution. Answers 'which features matter most overall', while the beeswarm answers 'how they matter'.

Fig_8 - False Positive analysis - for the features most linked to false-positive errors, distributions across the training class 0 group, correctly-predicted negatives (TN), and the false positives (FP). Shows where the model gets fooled into predicting risk that isn't there.

Fig_9 - False Negative analysis - same idea for false negatives: distributions across training class 1, correctly-predicted positives (TP), and false negatives (FN). Shows which value ranges of a feature cause the model to miss real at-risk respondents.
